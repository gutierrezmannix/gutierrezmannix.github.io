# T-tests — validation (build 2026-11-02.64)

Tests ▾ → T-tests has four designs: two independent groups, paired measurements, one sample against a value, and
summary numbers. Build .62 redesigned the page (see `COMPARE-MEANS.md`): one sentence sets up the test, and it adds
one-sided tests and Word exports. The statistics below are unchanged.

## What the page does

- **Two independent groups.** Welch’s test (unequal variances) by default, or **Student’s test** (equal variances,
  pooled standard deviation, n₁ + n₂ − 2 degrees of freedom) with one click under *Variances*. The difference is
  the first group minus the second. With two groups, the first is the lower code (or the first name
  alphabetically), as Stata and R report them; **⇄ Order** swaps them. With more than two groups, you pick
  group A and group B. The results table shows each group, Stata’s *Combined* row and the difference.
- **Paired measurements.** Rows missing either value are removed together. The effect size is **d_z** (mean
  difference ÷ standard deviation of the differences), labelled as such. It is usually larger than Cohen’s d
  for the same data.
- **One sample.** Mean against a reference value; Cohen’s d = (mean − value) ÷ SD.
- The tests are classical and unweighted, two-sided by default (one-sided under *Test*). A weight variable blocks them rather than giving a wrong
  standard error. The IF subgroup and missing-value codes apply.

## Console

| Typed | Test |
|---|---|
| `ttest y, by(g)` | Student’s (Stata’s default), with the Combined row |
| `ttest y, by(g) unequal` | Welch, Satterthwaite’s degrees of freedom (opens the page) |
| `ttest y, by(g) welch` | Welch, Welch’s (1947) degrees of freedom, as Stata’s `welch` option |
| `ttest y == 50`, `ttest a == b` | one sample, paired (opens the page) |
| `t.test(y ~ g, data = df, var.equal = TRUE)` | Student’s |

Other options are refused, as in Stata (`ttest y, by(g) foo(3)`: option foo() not allowed). `level(#)` and R’s `conf.level` apply to that command only, as an `if` does: the next command is back at the
confidence level set in Settings (or with `set level`).

## Validation

`tests/ttest-reference.test.mjs` compares the page’s engine with SciPy on 150 stored cases
(`tests/data/ttest-reference.json`, regenerated by `python3 calculator/tests/ttest-reference.py`): one sample,
paired, Welch and Student tests, and Stata’s `welch` degrees of freedom; n from 2 to 400, values from 10⁻⁶ to 10⁸,
missing values, confidence levels from 90% to 99.99%. Estimate, t, df, p and the confidence limits agree within
10⁻⁸ (relative). It runs with every `node --test` and needs neither Python nor R. It also checks the group order
and swap, Student’s option and its Stata/R commands, `level()` for one command, and d_z.

The earlier R comparison (90 cases with R 4.3.3 `stats::t.test`) can still be run:

```sh
Rscript calculator/tests/ttests-reference.R /tmp/gm26-ttests
GM26_TTEST_R_DIR=/tmp/gm26-ttests node calculator/tests/ttests.test.mjs
```

The page is `src/compare-means.js` (validated against SciPy by `tests/compare-means.test.mjs`); the t-test code it
reuses lives in `src/app/component.js` (`ttRecord`, `ttCommands`, `ttGroups`, `stataTtestSummary`,
`ttStataText`, `ttRText`) and `src/app/engine.mjs` (`ttDetails`, `oneSampleT`, `pairedT`, `ttCritical`); the console
printouts for `by()` and `welch` are in `src/console-stata.js` (`cxTtestPooled`).

Build .64: a one-sided test after ⇄ swap (or with groups picked high-to-low) exports R's alternative in R's own order
("first > second" on the page is `alternative = "less"` in R), checked in `tests/regression-numerics.test.mjs`.
